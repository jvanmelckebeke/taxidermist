# taxidermist

Keeps the YAML frontmatter in a tree of markdown files, and plain YAML files such as
a repo's config lists, to a schema you declare. The schema is a directory of YAML
files. taxidermist checks frontmatter and YAML files against it, and blocks the
commit when a staged file uses a value nobody defined. It also generates one how-to
page per document type, so writing frontmatter takes a single read.

It exists because frontmatter drifts. A filter only works if everyone spells the
value the same way, and a coined `obs_type: event` doesn't break anything loudly: it
makes the file unfindable by the query that should reach it. In the knowledge base
this was extracted from, the first run found 66 such values.

## Install

```sh
go install github.com/jvanmelckebeke/taxidermist/cmd/taxidermist@latest
```

From a clone: `go install ./cmd/taxidermist`.

Each `v*` tag publishes a GitHub release with
`taxidermist_<version>_<os>_<arch>.tar.gz` for linux/amd64, linux/arm64 and
darwin/arm64, the binary at the archive root, and a `checksums.txt` of sha256 sums.

## The schema

A `taxonomy/` directory, next to the content it governs. [`example/`](example/) is a
small complete one.

```
taxonomy/
├── scope.yaml           the directories it governs, unknown doctypes, folder-name rules
├── exempt.yaml          declared grandfathering: a path glob and the fields it may omit
├── traits.yaml          field bundles a doctype composes
├── singletons.yaml      shared fields that form no bundle, each naming its doctypes
├── vocabularies/        value lists shared by several fields, one file each
├── types/<slug>.yaml    one file per doctype: its traits, field set and own fields
├── house-rules.md       optional, hand-written: leads the generated index page
└── format/              GENERATED by `taxidermist docs`, one page per doctype and
                         one per vocabulary under format/vocabularies/
```

Paths in `scope.yaml`, `exempt.yaml`, `directory:`, `files:`, `from:` and
`reference:` are relative to the taxonomy directory's parent. Nothing inside the
taxonomy directory is checked, even under a root of `.`: it holds the schema and the
generated `format/` pages.

A root in `scope.yaml`'s `roots:` is a directory, which governs everything under it,
or a single file, which governs that file and nothing beside it.

A document's `type:` selects its schema. A type file declares that doctype's
`required` and `optional` fields; a key in neither list is a fault. It can also
compose `traits`, add `required_when` conditions and define its own `fields`. The
literal `type:` value defaults to the file stem; set `type:` in the file when the
value is not slug-shaped (`type: Project Plan` in `types/project-plan.yaml`).

A type file's `directory:` names the folder its pages live in. A `{field}` in it is
filled from the page's frontmatter, so with `directory: collections/{kind}` a page
with `kind: pose` must sit in `collections/pose/`, and anywhere else is a `value`
fault. A placeholder whose field is optional and absent drops out of the path:
`directory: conventions/{kind}` puts a convention with no `kind` directly in
`conventions/`. A placeholder must name a field the type declares. Every page's
filename stem, `index.md` aside, must also be unique under the part of the path before
the first placeholder, searched recursively, so `collections/pose/x.md` and
`collections/wardrobe/x.md` are both faults.

A field is described by these keys:

| key | means |
|---|---|
| `value` | `str`, `date`, `bool`, `int`, `float`, `list`, `object`, `map`, or an `a\|b` union. `float` accepts ints |
| `definitions` | value → its meaning. The keys are the allowed values; there is no second list |
| `vocabulary` | the name of a file in `vocabularies/` whose definitions are the allowed values |
| `reference` | a directory whose page slugs, searched recursively, are the allowed values, so the list grows by adding a page. `reference: stories/*` takes the names of the folders directly under `stories/` that hold an `index.md` instead; the pages inside them are not values. `reference: gitea/repos.yaml`, a YAML file, takes that file's top-level keys |
| `pattern` | a regular expression every value, or every item of a list, must match |
| `schema` | for `value: object`, the nested keys, each described the same way. For `value: map`, the keys of every value |
| `key` | for `value: map`, what every key must be: a `pattern`, `vocabulary`, `definitions` or `reference` |
| `values` | for `value: map` whose values are not mappings, the spec every value meets |
| `items` | for a `value: list` of mappings, the keys of every element |
| `required` | on a nested key: it must be present |
| `excludes` | another field of the same document; no value here may repeat its value. `also_themes` with `excludes: theme` can't list the file's own `theme` |
| `dynamic` | the value set changes too often to enumerate; the type is still checked |
| `applies_to` | in `singletons.yaml`, the doctypes that carry the field |
| `guidance` | what to put there, rendered on the format page |

A meaning is a one-line string, or a mapping with `means:` and `not:` when a
neighbouring value is easy to confuse with it:

```yaml
definitions:
  hiring: Recruiting, interviews, onboarding.
  infra:
    means: Servers, deploys, the build.
    not: Hiring for the infra team; that is `hiring`.
```

The format pages print `not:` in its own column. A vocabulary file in
`vocabularies/` has the same `definitions:` mapping, and may nest values one level
under group names; a group can't hold a value called `means` or `not`.

A `value: map` is a mapping whose keys are names rather than fields, such as topic
name to its meaning. `key:` checks the names and `values:` or `schema:` checks what
each one holds:

```yaml
labels:
  value: map
  key:
    pattern: '^[a-z]+$'
  values:
    value: str
    guidance: What the label marks.
```

A value can only exist once someone has written down what it means. If nothing fits,
add the value to the schema with its definition, in the same commit that uses it.

`scope.yaml` sets `ungoverned: error` (the default) to make a document whose doctype
has no type file a fault, or `ungoverned: report` to tally those documents instead.
Use `report` while adopting the schema on a tree full of doctypes you haven't
written up yet.

`invocation:` in `scope.yaml` is how the repo runs taxidermist, and the generated
pages print it wherever they name a command. `{command}` marks where the subcommand
goes; without it the subcommand is appended. It defaults to `taxidermist`. A repo
with a pinned wrapper sets `invocation: bin/taxidermist`, or
`invocation: tools/taxidermist {command} --taxonomy kb/taxonomy` when the taxonomy is
not at `./taxonomy`.

## Folder names

`segments:` in `scope.yaml` ties the names directly under a directory to a vocabulary
or a regular expression. The first path component under the directory is the name:
a folder, or the stem of a page sitting directly there. `projects/infra.md` and
`projects/infra/build-cache.md` both name `infra`; deeper folders are not
checked. `index.md` and `README.md` directly in the directory describe the directory
itself and name nothing.

```yaml
segments:
- path: projects/*
  vocabulary: topic
  field: topic
- path: people/*
  pattern: '^[a-z][a-z-]*$'
```

A rule takes exactly one of `vocabulary` and `pattern`. A name off the list is a
`segment` fault, so `projects/foobar/plan.md` can't be committed until `foobar` is
defined. A vocabulary value with no folder is fine; `check --facets` lists those.

`field` is optional. When the file's value for that field differs from the folder
it sits in (for a list, when the folder is not among its items), `check` and `hook`
print a `mismatch` warning. Warnings never fail a run; they print as one line per
folder, and `--verbose` lists every file.

## Plain YAML files

A type file with `files:` governs plain YAML files instead of frontmatter. The
glob is matched against the file's path, and a `.yaml` or `.yml` file under a
governed root takes the doctype whose glob matches it. The path decides the
doctype, not a field, since many such files have nowhere to put a `type:` key. A
file no glob matches is ungoverned, which `ungoverned: error` makes a fault and
`ungoverned: report` tallies under `<yaml>`. Two globs matching one file is a fault
in `check` and in `lint`. Until some type has `files:`, YAML files are not checked
at all. Markdown keeps choosing its doctype with `type:`.

`shape:` says what the file's top level is:

- `fields`, the default: the top-level mapping is the field set, checked as a
  frontmatter block is.
- `map`: every top-level key names an entry, and every entry is checked against the
  field set. `key:` checks the names, with `pattern:`, `vocabulary:`,
  `definitions:` or `reference:`.
- `list`: every item is checked against the field set.

```yaml
# taxonomy/types/team.yaml
files: config/teams.yaml
shape: map
key:
  pattern: '^[a-z][a-z-]*$'
required: [purpose, lead]
optional: [topics]
fields:
  purpose:
    value: str
    guidance: What the team is for, in one line.
```

A fault names the path down to the key: `platform.archvied` for a key inside an
entry, `[2].team` for one inside a list item, `labels.WIP` inside a map field, and
`<file>` for the whole file. [`example/config/`](example/config/) has one file per
shape.

The format page for a YAML doctype is titled with its `files:` glob. Its "Copy
this" block is a whole file for `shape: fields`, one entry under a `<name>`
placeholder for `shape: map`, and one item for `shape: list`, with no `---` fences.

A vocabulary can take its values from a mapping in a governed data file, so the
file stays the one place they are declared:

```yaml
# taxonomy/vocabularies/team.yaml
from: config/teams.yaml   # the data file, in this repo
at: teams                 # optional: a dotted key path to the mapping; the top level when absent
means: purpose            # optional: the key in each entry that says what the value means
```

The mapping's keys are the allowed values, and each entry's `means:` key is the
value's meaning on the format pages. The `from:` file must be governed by a type, so
its own shape is checked before its keys become values. A change to it can leave
`format/` stale, so `hook` runs `docs --check` when it is staged.

Every vocabulary, listed or read, gets its own page at
`format/vocabularies/<name>.md` with its values table and where they are declared.

## Commands

```
taxidermist check [FILE ...]   check frontmatter and YAML files (default: every governed root)
    --facets                   every key and value in use per doctype, drift first
    --ungoverned               list the files whose doctype has no schema
    --kind value,missing       only these fault (or warning) kinds
    --verbose                  list every warning and segment fault per file
    --stdin-filename PATH      check stdin as the markdown or YAML file at PATH, which need not exist
    --json | --toon            machine-readable output
taxidermist docs [--check]     generate taxonomy/format/, or fail if it is stale
taxidermist lint               check the schema against its own invariants
taxidermist hook               the pre-commit gate
```

Every command takes `--taxonomy DIR` (default `taxonomy`). Exit codes: 0 clean,
1 faults, 2 a usage or schema error.

`check` reports seven kinds of fault: `value` (a value that isn't allowed, misses
its `pattern`, or repeats the field its spec `excludes`, and a YAML file no doctype
or two doctypes match), `type`, `missing` (a required field is absent), `unknown`
(an undeclared key), `shape` (wrong keys inside an object or list item), `parse` (a
block that opens and doesn't parse, which leaves the file invisible to every
reader, or a YAML file that doesn't parse) and `segment` (a folder name off its
vocabulary). It also reports one kind of warning, `mismatch`, which doesn't change
the exit code.

`--stdin-filename` checks content before it is written anywhere. PATH still decides
a YAML file's doctype, the folder rules, the exemptions and the slug, so it must
sit under a governed root; one that does not is a usage error (exit 2), not a
silent skip.

`lint` also checks that each segment rule's directory exists under a governed root
and that its `field` is one some doctype declares. A rule naming a vocabulary that
doesn't exist, or a pattern that doesn't compile, is a schema error. It flags an
`excludes` naming a field that some doctype carrying the field doesn't declare, an
`excludes` on a nested key, which nothing checks, a `files:` glob under no governed
root, and a YAML file that two doctypes' `files:` match.

## JSON output

`check --json` prints one object. The Python package and other callers parse it, so
its shape is a contract: removing or retyping a key is a breaking change, adding one
is not. Read the keys you know and ignore the rest; the Python package does.

```json
{
  "governed": 1,
  "faults": [
    {
      "file": "notes/x.md",
      "kind": "missing",
      "field": "topic",
      "value": null,
      "why": "required on `note`"
    }
  ],
  "warnings": [],
  "ungoverned": {}
}
```

- `governed` counts the checked files whose doctype has a schema.
- `faults` fail the check (exit 1). `warnings` never do, and their `kind` is always
  `mismatch`. Both are arrays, empty rather than null, in file order.
- `file` is relative to the working directory when the file sits under it, absolute
  otherwise.
- `kind` is the rule that fired: `value`, `type`, `missing`, `unknown`, `shape`,
  `parse`, `segment` or `mismatch`.
- `field` is the key, as a dotted path when it sits inside an entry, an item or a
  mapping (`platform.archvied`, `[2].team`, `review.open`), or `<frontmatter>`,
  `<file>`, `<slug>` or a folder rule's path when the finding is about no single key.
- `value` is the offending value as YAML text, or null when there is none, as for a
  missing field.
- `why` says what is wrong and what the schema allows.
- `ungoverned` maps a doctype with no `types/` file to its files, when scope.yaml
  says `ungoverned: report`.

`--kind` filters `faults` and `warnings` before printing. Exit 2 prints nothing on
stdout and the reason on stderr.

## From Go and Python

The root package is the library behind `check --json`:

```go
import "github.com/jvanmelckebeke/taxidermist"

tax, err := taxidermist.Load("taxonomy")
r, err := tax.Validate("notes/a.md", "notes/b.md") // no paths: every governed root
r, err = tax.ValidateContent("notes/new.md", content) // content as that file
for _, f := range r.Faults {
	fmt.Println(f.File, f.Kind, f.Field, f.Why)
}
```

The Python package in [`python/`](python/) runs the binary with `--json` and returns
the same result as dataclasses:

```sh
pip install "git+https://github.com/jvanmelckebeke/taxidermist#subdirectory=python"
```

```python
import taxidermist

r = taxidermist.validate("notes/a.md", taxonomy="taxonomy")
r = taxidermist.validate_content(card_text, "backlog/new.md", taxonomy="taxonomy")
if not r.ok:
    for f in r.faults:
        print(f.file, f.kind, f.field, f.value, f.why)
```

It runs `$TAXIDERMIST_BIN` when set, otherwise `taxidermist` on PATH. It raises
`BinaryNotFound` when there is neither, `BinaryTooOld` for a release before 0.6.0,
and `TaxidermistError` for a broken taxonomy or a bad path. A build that reports
version `dev`, such as one from `go install`, is accepted.

The package does not ship the binary yet. Wheels that bundle it per platform, the
way ruff and uv do, are a later option.

## Pre-commit

`taxidermist hook` reads the staged file list itself. When anything under the
taxonomy, or a data file a vocabulary reads with `from:`, is staged, it runs
`docs --check`. It then runs `check` on the staged markdown and YAML only, including
the new path of a renamed file, so moving a page into an undefined folder is caught. A repo-wide gate would block every commit until the
whole backlog is fixed, and a hook like that ends up bypassed with `--no-verify`
for good.

In a hand-written `.git/hooks/pre-commit`, or a tracked hooks directory:

```sh
taxidermist hook --taxonomy taxonomy || exit 1
```

With the [pre-commit](https://pre-commit.com) framework:

```yaml
repos:
- repo: https://github.com/jvanmelckebeke/taxidermist
  rev: v0.2.0
  hooks:
  - id: taxidermist
    args: [--taxonomy, taxonomy]
```

pre-commit refuses to install while `core.hooksPath` is set, so pick one of the two.

## YAML

Frontmatter and YAML files are parsed as YAML 1.2 by [yaml.v3](https://github.com/yaml/go-yaml).
`2026-04-01` is a date and `value: date` accepts it; `2026-02-30` is a string, so
it fails a `date` field. `yes` and `off` are strings, not booleans: write `true` and
`false`. A key written twice in one block does not parse.

In a field spec or a type file, an unknown key is a schema error, so a typo like
`defintions:` stops the load instead of leaving a field that checks nothing.
